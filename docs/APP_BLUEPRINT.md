## 1. 产品概述

### 1.1 产品定位

「记了么」是一款本地优先的 Android 个人记账 App，主要解决：

- 快速手动记录收入、支出和转账；
- 根据支付宝、微信支付通知生成预添加记录；
- 导入支付宝、微信官方账单，补全历史数据并核对；
- 管理账户余额、转账手续费、AA 分摊和退款；
- 查看月度预算、收支和分类统计；
- 通过本地备份保护数据；
- 通过 GitHub Releases 获取新版本。

### 1.2 核心原则

1. **本地优先**：账单和通知内容不上传服务器。
2. **流水真实**：原始支付、回款、退款和转账流水不得被统计口径篡改。
3. **统计清晰**：AA 回款和退款用于冲减支出，不计普通收入。
4. **不确定就确认**：通知识别信息不足或关联不可靠时进入待确认。
5. **可恢复**：支持完整备份与恢复，覆盖升级必须保留数据。
6. **简单实用**：优先满足个人自用，不为不必要的高级功能增加复杂度。

### 1.3 已确定的基础选择

| 项目 | 决定 |

## 3. 基础交易与账户

### 3.1 主交易类型

首版主类型保持为：

- 支出；
- 收入；
- 转账。

退款通过“收入 → 这是退款”实现；AA 回款通过支出内的 AA 功能关联，不作为第四种主交易类型。

### 3.2 通用交易字段

- 金额；
- 发生日期和时间；
- 账户；
- 分类；
- 商户或交易对方；
- 备注；
- 来源：手动、支付宝通知、微信通知、官方文件导入等；
- 状态：预添加、正式、已忽略等；
- 创建和修改时间。

### 3.3 账户

默认账户建议：

- 支付宝；
- 微信支付；
- 现金；
- 银行卡。

账户支持：

- 自定义名称和颜色；
- 设置初始余额；
- 显示当前余额；
- 是否计入首页总余额；
- 停用账户；
- 余额校准。

### 3.4 余额口径

账户余额必须根据实际资金流水计算：

```text
当前余额 =
初始余额
+ 已确认普通收入
+ 已确认 AA 回款
+ 已确认退款
+ 已确认转入
- 已确认支出
- 已确认转出
- 本账户承担的手续费
± 余额校准记录
```

规则：

- 预添加、待确认和已忽略记录不影响余额；
- 首页总余额为所有“计入总余额”账户的余额之和；
- 新增、编辑、删除、关联或取消关联后必须重新计算；
- AA 与退款虽然冲减统计支出，但仍按实际到账账户增加余额；
- 停用账户不等于删除历史流水。

## 4. 转账与手续费

### 4.1 转账字段

- 转出账户；
- 转入账户；
- 转账金额；
- 手续费方式：无手续费／固定金额／百分比；
- 固定手续费金额或百分比费率；
- 最终手续费；
- 备注。

### 4.2 计算规则

默认由转出账户额外承担手续费：

```text
百分比手续费 = 转账金额 × 费率
转出账户减少 = 转账金额 + 最终手续费
转入账户增加 = 转账金额
```

示例：转账 1,000 元，手续费率 0.1%：

```text
最终手续费：1 元
转出账户：减少 1,001 元
转入账户：增加 1,000 元
```

### 4.3 统计规则

- 转账本金不计收入或支出；
- 转账本金不占预算；
- 自动计算的手续费允许手动修改；
- 手续费进入“转账手续费”支出分类；
- 手续费影响账户余额、预算和支出统计；
- 保存前显示转出金额、到账金额和手续费预览。

## 5. AA 分摊与跨账户回款

### 5.1 页面入口

在新建或编辑支出页面提供“AA／分摊”开关。

开启后直接展开 AA 回款区域，每笔回款可填写：

- 收款金额，必填；
- 收款去向账户，必填；
- 付款人，选填；
- 收款时间，选填；
- 备注，选填。

支持“添加回款”保存多笔记录。按人数均分仅作为可选辅助计算，不强制填写。

### 5.2 页面示例

```text
支出金额：300 元
支付账户：支付宝
分类：餐饮
AA／分摊：已开启

回款 1：120 元 → 微信
回款 2：80 元 → 现金

原支出：300 元
已收回款：200 元
当前实际承担：100 元
```

### 5.3 核心规则

- 付款账户和回款账户完全独立；
- 支持支付宝付款、微信收款等跨平台场景；
- 支持多人、多笔、部分和跨账户回款；
- 原支出和每笔回款保留独立流水；
- 不直接修改原支出金额；
- 回款增加实际收款账户余额；
- AA 回款不计普通收入；
- 未收到回款时不提前冲减预算；
- 后续可打开原支出补录回款；
- 收款通知可建议关联已有 AA 支出；
- 仅凭金额相同无法可靠判断时必须由用户确认。

### 5.4 AA 统计

```text
AA 后的实际净支出 = 原支出 - 已关联 AA 回款
```

- 分类支出和预算按已回款后的净支出更新；
- 首页总余额按真实账户流水更新；
- 展示原支出、已收、待收和实际承担；
- 取消关联或删除回款后自动重新计算；
- 回款合计超过原支出时提示异常，由用户确认。

## 6. 退款

### 6.1 页面入口

在收入页面提供“这是退款”选项。开启后填写：

- 关联原支出；
- 退款金额；
- 退款到账账户；
- 退款时间；
- 备注。

退款到账账户不强制与原支付账户相同。

### 6.2 核心规则

- 支持全额、部分、多次和跨账户退款；
- 原支出流水保持不变；
- 退款按实际到账账户增加余额；
- 退款不计普通收入；
- 退款同步冲减关联支出的净支出、分类统计和预算；
- 取消关联或删除退款后自动重算；
- 删除原支出时不得级联删除退款流水，应提示并标记为“未关联退款”；
- 退款超过可冲减金额时提示异常，由用户确认。

### 6.3 AA 与退款统一口径

```text
实际净支出 =
原支出
- 已关联 AA 回款
- 已关联退款
```

示例：原支出 300 元，AA 回款 100 元，之后退款 50 元：

```text
最终实际净支出：150 元
普通收入：不增加
预算与分类统计：按 150 元净支出更新
账户余额：仍按各笔真实支付和到账流水计算
```

AA 回款与退款合计超过原支出时必须提示，避免统计出现非预期负数。

## 7. 通知预添加与自动入账

### 7.1 处理流程

```text
读取用户授权范围内的支付宝／微信通知
→ 本地提取金额、时间、商户、收付款方向
→ 匹配账户、分类和可能的 AA／退款关联
→ 生成预添加记录或高置信度自动入账
→ 后续通过官方账单导入核对
```

### 7.2 手动确认模式（默认）

- 所有识别结果进入预添加列表；
- 展示来源、金额、商户、时间和原始通知；
- 支持确认、修改后确认、忽略和删除；
- 确认前不影响余额、预算和统计。

### 7.3 自动入账模式

提供“自动添加进账单”开关：

- 仅金额、方向和账户明确的记录可自动入账；
- 信息不足、方向不明或关联不可靠时仍需确认；
- 自动入账记录允许编辑；
- 自动入账不等于自动关联 AA 或退款；
- 自动关联必须具有足够依据，否则进入待确认。

### 7.4 隐私与稳定性

- 只处理用户明确授权的支付宝、微信通知；
- 原始通知和解析结果仅保存在本地；
- 不保存支付密码、Cookie、登录令牌；
- 不采用模拟登录、抓包或无障碍翻页；
- 对重复通知进行去重；
- 通知格式变化导致无法解析时不得猜测入账。

## 8. 官方账单导入

### 8.1 导入方式

- 系统文件选择器；
- 其他 App 分享到「记了么」；
- 根据真实导出样本支持 CSV、常见 Excel 或官方压缩包格式。

### 8.2 导入流程

```text
选择文件
→ 识别来源和格式
→ 解析
→ 预检新增／重复／异常
→ 用户确认
→ 写入正式账单
→ 输出导入结果
```

### 8.3 数据质量要求

- 同一文件重复导入不产生重复账单；
- 与通知生成记录匹配时避免重复；
- 不确定的合并不得静默执行；
- 导入前可查看异常；
- 导入后显示新增、重复、失败和跳过数量；
- 保存导入批次和必要原始记录，便于重新解析和排错。

## 9. 预算与统计

### 9.1 月度总预算

- 用户手动设置和修改每月预算；
- 首页显示已用、剩余和使用比例；
- 接近或超过预算时显示提示；
- 转账本金不占预算；
- 转账手续费计入预算；
- AA 回款和退款按实际已关联金额冲减；
- 预添加记录不占预算。

### 9.2 统计口径

- 普通收入不包含 AA 回款和退款；
- 分类净支出扣除已关联 AA 回款和退款；
- 账户余额始终按实际资金流动计算；
- 转账本金与手续费分开统计；
- 所有统计都应能追溯到对应明细。

### 9.3 后续需要明确的实现细节

- 跨月 AA 回款和退款对历史月份、到账月份预算的展示方式；
- 首页“本月支出”是否同时提供毛支出／净支出切换；
- 未关联退款在统计中的单独展示方式。

这些细节在统计模块实施前补充，不改变流水和关联数据结构。

## 13. 技术设计速查

> 本章为当前计划，实际实现后更新为真实结构与模块说明。

### 13.1 技术栈

- Kotlin；
- Jetpack Compose；
- Material 3；
- Room／SQLite；
- Android Storage Access Framework；
- NotificationListenerService；
- AndroidX Biometric；

### 13.2 金额与时间

### 13.3 初步数据实体

| `Account` | 账户、初始余额、是否计入总余额、停用状态 |
| `Category` | 收入／支出分类、排序、图标和颜色 |
| `Transaction` | 支出、收入、AA 回款、退款等实际流水 |
| `TransferDetail` | 转出、转入、手续费方式、费率和最终手续费 |
| `TransactionLink` | 将 AA 回款或退款关联到原支出 |
| `CategoryRule` | 商户关键词到账户或分类的映射 |
| `ImportBatch` | 文件导入批次、结果和错误信息 |
| `RawRecord` | 通知或导入原始记录及解析状态 |
| `AppSetting` | 预算、外观、自动入账等设置 |

最终字段、索引和数据库版本以实际 Room 实现为准，并在此处补充。

### 13.4 关键实现约束

- AA 和退款必须保存关联关系，不能只修改统计数字；
- 预添加与正式交易必须有明确状态；
- 删除、取消关联和数据库迁移必须保持可恢复；
- 去重需要综合来源、外部交易号、时间、金额和对方信息；
- 网络更新失败不能影响任何本地功能。
